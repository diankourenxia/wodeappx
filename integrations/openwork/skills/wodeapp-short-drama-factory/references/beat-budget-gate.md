# Beat Budget Gate（内容先估秒，再组镜头）

> 用来避免「剧本只有 60s 料，视频脚本却灌成 120s」。  
> **先过章节充足度门（Gate 0）→ 拆成可见节拍 → 由文字模型判断时间轴 → 加总定集长 → 再合并成可执行镜头。禁止先定 8×15s 再往里填。**
>
> Gate 0：`references/chapter-content-sufficiency.md`（章节事件够不够撑目标时长）  
> 本文件是 Gate 1：剪辑节拍 ↔ AI 镜头合并

## Two Layers（不要混）

| 层 | 是什么 | 典型粒度 |
|----|--------|----------|
| **剪辑节拍** | 一条可见变化（丝带滑落、一句对白） | 由文字模型结合完整表演判断，可与相邻动作/对白并行 |
| **AI 可执行镜头** | 送给视频模型的一条 clip | 普通 **12–15s**；钩子/插入/反应 **4–8s**；最低 **4s**（`shortDramaContracts.durationPolicy`） |

「指尖发白」可以是剪辑节拍，但不能因为它独占一行就固定加 N 秒。模型应判断它是否与对白、道具动作同时发生；组成 AI clip 时再遵守引擎的最低时长。

## Root Cause（为什么会灌水）

| 错误顺序 | 正确顺序 |
|----------|----------|
| 先定「本集 120s / 8 镜」 | **先**确认章节事件撑得住目标时长（Gate 0） |
| 每个镜头默认 15s | 列出剪辑节拍并估秒，再合并成 AI 镜 |
| 不够就加日常、眼神、空镜 | 不够就扩写事件或降低目标时长 |
| 大纲钩子来不及塞进最后一镜 | 集末钩子先占预算，再排前面 |

快节奏竖屏：**内容决定时长，时长不决定内容。**

## Step 1 — Beat Inventory（段落拆条）

把本集剧本拆成独立节拍表（一场可多条）。每条只写一件可见事：

```text
beatId | 内容（一句话） | 功能 | 估秒 | 可否删除
E01-B01 | 花坊系丝带 | establish | 模型判断 | 可压缩
E01-B02 | 周叔放公文包 | trigger | 模型判断 | 否
...
E01-B18 | 字迹=父亲笔记 | cliffhanger | 模型判断 | 否（本集钩）
```

功能标签（自由写，不必枚举）：`establish` / `trigger` / `pressure` / `decision` / `payoff` / `clue` / `cliffhanger` / `bridge`

规则：

- **一条 = 一个可见变化**（动作、道具、关系、线索、一句短台词）
- 内心戏必须改成可见外化后再估秒
- 大纲里的集末钩（字迹对照、身份露馅等）**必须出现在表里**；表里没有 = 脚本漏钩

## Step 2 — Model Timing Judgment（模型判断时长）

把完整正文和节拍表一起交给文字模型。让模型输出：

- `contentEstimateSec`：整集的可拍时长
- `playbackTimeline[]`：场次/重要节拍/结束的累计时间点
- 可选的 `beatTimings[]`：每个节拍的模型判断秒数，用于组镜

模型必须同时考虑：

- 动作与对白是顺序发生，还是可以边做边说
- 表演速度、必要反应、有意义的停顿
- 道具取放、观众读取线索、场景转换的真实需求
- 竖屏快剪能否并行、跳切或省略连接过程

**禁止的本地估时算法：**

- 每条 `△` 动作固定 N 秒
- 对白按每秒 N 个字换算
- 按行数、标点或动作类型查表加总
- 正文改动后沿用旧大纲/旧审核的时长

本地代码只做 schema 校验、时间轴单调性检查、汇总与 Gate 对比；**不自行创作任何正文秒数**。正文被编辑后，时长必须标记为过期并重新调用模型。

## Step 3 — Episode Budget（加总定集长）

```text
episodeBudgetSec = sum(各节拍估秒)
```

| `episodeBudgetSec` | 处理 |
|--------------------|------|
| **55–75** | 快节奏默认甜区；直接进入组镜 |
| **76–90** | 可接受；检查是否有可删建立/VO |
| **91–120** | 必须证明每个 >8s 的节拍不可压缩；否则砍 |
| **>120** | P0：拆集或删支线，禁止靠空镜撑满 |

若用户目标是 120s 但 `episodeBudgetSec` 只有 ~70s：回到 Gate 0 **扩写章节**，不要在本步注水。

快节奏竖剧默认目标：**60–75s/集**，不是 120s。  
120s 只在用户明确要求、**且** Gate 0 事件库存达标时使用。

## Step 4 — Pack Shots（节拍合并成 AI 镜头）

把相邻、同场、同主体的节拍合并成可执行镜头：

| 规则 | 说明 |
|------|------|
| 每镜最多 **2** 个动作节拍 | 与 manifest `actionBeats` 上限一致 |
| 每镜时长 = 所含节拍秒数之和 | **不要**先写 15 再凑戏 |
| 合并后若 ≥12s 且戏够 | 可落在 12–15s 工作台甜区 |
| 硬钩 / 特写 / 反应 | 保持 4–8s，不要拉到 15 |
| 一镜里出现 3 个以上情节点 | P0：拆镜（如领证+对白+上车） |
| 单镜 <4s | 并入邻镜或扩到 ≥4s（工作台最低） |

示例（假设某次模型给出下列时间；这些秒数不是模板，不得复用到其他正文）：

```text
Shot1  5s    B01 建立（短镜）
Shot2  12s   B02–B04 进门+协议+丝带落
Shot3  12s   B05–B07 拒绝+重启调查+掐掌心
Shot4  8s    B08–B09 悬笔+签字
Shot5  8s    B10–B11 并排+各取所需
Shot6  7s    B12–B14 塞证+嗯+离开
Shot7  10s   B15–B17 纸条
Shot8  8s    B18 字迹对照钩
合计 ≈ 70s
```

## Step 5 — Density Review（灌水检查，写分镜前必跑）

### P0（不过不能出视频脚本）

- Gate 0 未通过仍进入本步
- 先定总时长/镜数，再倒推内容（无 beat inventory）
- `sum(shot.durationSec)` 比 `episodeBudgetSec` 多出 **≥25%**，且多出部分是建立/空镜/纯反应
- 开场建立镜占比明显过高，且无新线索、无提问
- 大纲/剧本集末钩未进入任何 shot
- 单镜塞入 **≥3** 个独立情节点
- 整集默认「N×15s」且多数镜对白+动作撑不满 8s

### P1（警告）

- 主题总结 VO 占用显著篇幅
- 连续两镜无信息增量（无道具/关系/线索变化）
- 犹豫类特写（悬笔、对视）挤占了本应给新事件的时间
- 人物提示词气质与功能冲突（逼签却「面容慈祥」）

### OK

- 节拍表加总与目标匹配，镜头由合并得到，钩子在结尾落地

## One-line Rule

**有多少秒的戏，就做多长的集；不够就扩写或降目标，绝不加水。**
