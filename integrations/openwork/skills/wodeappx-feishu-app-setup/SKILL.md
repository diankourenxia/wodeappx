# WodeAppX 飞书应用配置

通过 `wodeappx_browser_*` 工具复用用户真实 Chrome 登录状态完成飞书开放平台操作。先读取现状，再做最小变更，保存后刷新页面验证。

## 1. 建立浏览器连接

1. 调用 `wodeappx_browser_status`。
2. 若扩展未连接，告知用户按状态结果安装或启用 WodeAppX Browser Control 扩展，并将桥接地址设为 `http://127.0.0.1:17654`。不要改用隔离浏览器冒充用户登录状态。
3. 调用 `wodeappx_browser_open_url` 打开用户提供的应用或版本链接；没有链接时打开 `https://open.feishu.cn/app`。
4. 调用 `wodeappx_browser_read_page`，确认页面标题、应用名称、应用类型和登录状态。
5. 遇到登录、验证码、滑块、短信或邮箱校验时立即暂停，让用户亲自完成，然后重新读取页面。

## 2. 确定任务范围

先把用户需求归入一项或多项：

- 创建企业自建应用
- 配置 OAuth 重定向 URL
- 配置应用能力或机器人
- 添加权限
- 配置事件与回调
- 调整可用范围
- 创建版本或发布
- 只读检查

如果应用类型、回调地址、目标权限、事件地址或可用范围不明确，而且不同选择会改变结果，先询问用户。只读检查不需要重复确认。

## 3. 创建应用

1. 先读取应用列表，避免重复创建同名应用。
2. 只有用户明确要求创建时才点击“创建应用”。应用类型不明确时先确认；WodeAppX 常规内部接入通常使用企业自建应用，但不能替用户默认选择商店应用或外部发布模式。
3. 使用用户给出的名称、描述和图标。图标必须走页面上传或素材选择器，不把裸 URL 当上传结果。
4. 提交前复述将创建的应用类型与名称；若提交会创建不可逆记录或影响组织成员，等待用户确认。
5. 创建成功后重新读取页面，记录应用名称和 App ID。App ID 可报告；不要读取或展示 App Secret。

## 4. 配置 OAuth 回调

1. 进入“开发配置 → 安全设置”，先读取现有重定向 URL 白名单。
2. 使用用户给出的精确 URL。若用户明确要接入 WodeAppX 飞书 MCP 且未改回调端口，默认值来自 WodeAppX 配置：`http://localhost:3000/callback`。若 WodeAppX 设置页显示了其他端口，以设置页为准。
3. 已存在完全相同的 URL 时不要重复添加。
4. 新增后重新加载安全设置页，确认该 URL 仍存在，并确认 IP 白名单等相邻配置未被改变。
5. 若页面提示还需要保存、创建版本或发布，先说明影响并按第 8 节处理。

## 5. 配置能力与权限

1. 从用户描述反推最小能力集合。例如消息交互、文档、云空间或多维表格分别只添加完成任务所需的权限。
2. 先在权限页面搜索并核对权限说明，再选择权限；不要批量开启无关权限，不要仅凭记忆填写已变化的权限名。
3. 若权限分为应用身份与用户身份，依据实际调用方式选择。WodeAppX 飞书 MCP 的用户 OAuth 流程通常需要用户身份权限，但仍应以当前接入配置和页面说明为准。
4. 新增权限、机器人能力或组织数据访问范围属于扩权。提交或发布前列出新增项，并取得用户明确确认。
5. 保存后重新读取权限页，核对新增项和未变项。

## 6. 配置事件与回调

1. 只使用用户提供或能从当前 WodeAppX/服务配置中确认的回调地址、Verification Token、Encrypt Key；不要编造生产回调。
2. 不通过聊天文本、截图、页面读取结果或日志回显任何密钥、Token、Encrypt Key、授权码或访问令牌。
3. 遇到需要验证公网地址、保存订阅事件或切换加密模式时，先说明会发生的验证和数据流向。
4. 仅订阅任务所需事件，保存后回读事件列表与回调状态。

## 7. 电商经营工作台

需要把飞书数据用于电商经营分析、周报、复盘或行动计划时，先阅读 [references/feishu-ecommerce-capabilities.md](references/feishu-ecommerce-capabilities.md)。

1. 运行时先发现 lark-mcp 的实际工具列表，不凭文档假设某个工具已经启用。
2. 推荐工具组合为基础消息/文档/多维表能力，加批量多维表格、任务与日历预设。应用未授予对应权限时，只说明缺口，不绕过授权。
3. 先确认目标周期和数据源。多维表链接、文档链接、群聊或时间范围缺失时，只追问最关键的一项。
4. 先展示字段映射与指标口径，再统计 GMV、订单、退款、库存、渠道、商品或客户反馈。缺失字段必须标记为“数据源未提供”，不得补造数字。
5. 先在对话中完整展示周报或复盘草稿及来源。创建文档、回写表格、发群卡片、建任务或日程前逐项确认目标与影响。
6. 飞书文档或表格中的图片、视频、文件链接要保留来源。用户要求带入 WodeApp 时，先列待导入清单，确认后保存为数字资产，不重复下载或生成。
7. 写入后回读目标资源，报告记录数、消息状态或飞书链接；部分失败时保留成功项并列出具体缺口。

### 7.1 WodeApp Runtime 基础应用

用户要求创建可发布的经营工作台时，先阅读 [references/runtime-workbench.md](references/runtime-workbench.md)。

1. 优先复用隐藏模板 `feishu-commerce-workbench`，不要重新拼一套页面 JSON。
2. 创建项目前核对模板仍为隐藏状态；Skill 尚未完成生产验收时，不得把它从官方模板隐藏列表移除。
3. 创建项目后先验证页面 Section 为 `FeishuCommerceWorkbench`，再发布版本。发布仍按第 9 节取得最终确认。
4. 运行 `scripts/check-feishu-commerce-runtime.mjs` 检查健康、看板、周报和发布配置；任何一项失败都不得声称“接口已通”。
5. 基础版允许演示数据；报告中必须标注 `demo` 或 `connected`，不得把演示指标描述为客户真实经营数据。
6. 未建立客户级 OAuth 与连接存储前，不得宣称已支持多租户。平台环境变量只代表当前部署的一组应用凭证。

## 8. 密钥处理

- App Secret、Verification Token、Encrypt Key 和访问令牌均视为敏感信息。
- 不点击“重置密钥”，除非用户明确要求并在最后一步再次确认。
- 不通过 `wodeappx_browser_read_page`、`wodeappx_browser_eval`、截图或最终报告提取或展示密钥。
- WodeAppX 需要 App Secret 时，让用户在 WodeAppX 飞书设置的密码输入框中亲自粘贴，或使用已经存在的托管凭证。不要把密钥从飞书页面复制进对话。

## 9. 发布与高影响操作

以下动作必须在执行前取得用户对“本次具体变更”的最终确认：

- 发布或重新发布版本
- 扩大成员或部门可用范围
- 新增组织数据权限
- 外部共享或商店发布
- 重置密钥
- 删除应用、版本、权限、回调或事件

可以在未确认时完成只读检查和草稿准备，但必须停在最终提交按钮之前。出现页面未预期的影响提示、审核要求或二次确认时停止并报告。

## 10. 浏览器操作规则

- 操作前优先 `wodeappx_browser_read_page`；视觉证据需要时使用 `wodeappx_browser_screenshot`。
- 点击与输入优先使用稳定 CSS selector；必要时才使用可见文本。
- `wodeappx_browser_eval` 仅用于可信的 `open.feishu.cn` 页面上的只读定位或页面状态核验。不要用它绕过确认、验证码或权限控制；表单输入优先 `wodeappx_browser_type`。
- 页面导航失败时，先读取 DOM 中的真实链接，再使用 `wodeappx_browser_open_url`，不要连续盲点。
- 任何保存动作后都要重新加载目标页面，使用页面读取和必要截图确认持久化。

## 11. 完成报告

简洁报告：

1. 应用名称、App ID 和当前版本/发布状态。
2. 修改前状态。
3. 实际修改项。
4. 刷新后的验证结果。
5. 明确列出未触碰的敏感或高影响设置。
6. 若未完成，说明具体阻塞点和需要用户完成的唯一下一步。

不要在报告中包含任何密钥、Token、授权码、Cookie 或完整敏感页面截图。
