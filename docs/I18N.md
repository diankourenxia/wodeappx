# Internationalization

WodeAppX maintains English (`en`) and Simplified Chinese (`zh`) as its core product languages. GitHub READMEs also exist for the other desktop locales (`ja`, `vi`, `pt-BR`, `th`, `fr`, `ca`, `es`, `ru`).

## Runtime behavior

Language resolution follows this order:

1. the user's saved `openwork.language` preference;
2. the operating-system/browser locale;
3. English as the deterministic fallback.

Changing the language in Settings persists the choice. Missing non-core translations fall back to English instead of exposing an internal translation key.

## Source ownership

- Upstream locale catalogs: generated under `vendor/openwork/apps/app/src/i18n/locales/`
- WodeAppX maintained overlay: `integrations/openwork/i18n/oss-overrides.json`
- Locale initialization: `integrations/openwork/fork/apps/app/src/i18n/index.ts`

Do not edit generated locale files under `vendor/`. Add or change WodeAppX strings in the overlay and use `t("namespace.key")` in product code.

## Required checks

```bash
pnpm openwork:patch
pnpm i18n:check
```

The check rejects:

- Chinese text in the English catalog;
- a WodeAppX core key present in only one maintained language;
- missing maintained keys referenced by the core shell;
- forced migration to a particular language;
- missing English fallback coverage for core namespaces.

Other upstream locales remain available, but WodeAppX-specific strings currently fall back to English unless a contributor adds and maintains a complete overlay for that locale.
